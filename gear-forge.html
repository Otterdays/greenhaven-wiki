Gear Forge

The Gear Forge turns an item from a set of pixels into data. It lives beside the map painter and the model maker. Open it, pick a shape, snap parts together, dress a character, and every icon, held overlay and worn sheet the game reads comes out the same click.

What the Forge paints

Every item in the game has one or more of three looks, and the Forge authors all three:

  • Icon. A 16 x 16 sprite from the shared item-icon sheet. It appears in the Inventory, the map painter's Items panel, the panel inspector and every tooltip.
  • Held. The piece a wanderer carries in their hand - the axe you swing, the sword you point at a mob, the hammer you take to the anvil. One overlay sheet per item, frame-aligned with the player so it follows walk, run, swing, kneel and blink.
  • Worn. The piece a wanderer wears on their body - a helm on the head, a plate on the chest, a cape on the back. One overlay sheet per piece, snapped to the body's frame index so it never drifts.

Items are data

Before the Gear Forge an item's look was hand-painted pixel art in a script. Now it is a row in a table. The Forge reads that table to paint a preview and writes that table on Save. The world, the client, the painter and the panel all read the same data - one source, no drift.

The parts library

Weapons and tools are made of parts that snap together, socket to socket. The library ships today:

KindCountExamples
Hafts4Short, long, iron, wrapped grip. Held at their end.
Heads8Axe bit, broad axe, pick, spike pick, hammer, mace, short blade, long blade. Each names the item kinds it is for.
Pommels2Knob, gem. Hang under the haft's bottom.

Every part in the library is paintable in the Forge GUI. Adding a new part is one row in assets/gear/parts.json - the moment it is on the sheet, the Forge offers it. No new code, no rebuild.

The synthesiser

The Forge has a small item-generating dialog: describe it in plain words ("a bronze axe with a gemmed top"), or pick kind, tier, trim, gem and size by hand. A seeded PRNG turns the style into a small gallery of up to 24 distinct candidates, each with its own icon, and each one already snapped from parts. Same seed, same style, same items. Nothing is hidden or random on the player's side; it is only a fast way to see options.

  • Kinds - axe, pickaxe, hammer, mace, sword.
  • Tiers - a bronze-to-adamantite ladder the shared item palette already knows.
  • Gems - ruby, sapphire, emerald, amethyst, topaz, diamond.
  • Trims - plain, banded, gemmed. A banding brightens the head; a gem takes the chosen gem colour.

A candidate can be used as this item's look (with or without a new icon), or turned into a brand new item via Make a new item from it... which opens the New item panel pre-filled.

Dressing any humanoid

Every wearable piece fits any humanoid character the game ships - player, goblin, skeleton, zombie, troll, cow, merchant, king and the rest. Pick a character in the Forge, click the piece you want, and the preview paints it on the body in every pose. Colour roles (body, shade, trim, and an optional stripe) come from a small palette, so one item is one set of roles and every character can wear it in a different mix of inks.

Items show up in swings

When a wanderer swings an axe or a sword, the same held art the Forge painted rides the swing clip. The strike pose and the held overlay are on the same frame index, so the sword stays in the hand all the way through a slash, and the axe head points where it should on a hack.

The rules are still data

Under the Forge, every item is one row in the shared items registry, plus optional rows for equipment, weapons and tools. The Forge's Item rules panel edits those rows without a text box: pick the weapon class, set accuracy and power (a slider each), tick "also a skilling tool", and the item's kindEntry rule is honoured everywhere. New rows append; ids never renumber.

Where the output goes

  • Item data - the shared registry, one row per item.
  • Icon - one cell on the shared item-icon sheet.
  • Held overlay - assets/models/gear/<item>.json, one per item that is held.
  • Worn overlay - assets/models/gear/<item>.json, one per item that is worn.

The client, the world, the map painter and the panel read all four from one place. Save in the Forge and every tool sees the change the next time it loads.

Checks and one-click fixes

The Forge has a lint engine with thirteen rules and a Checks panel that runs them live. Each finding shows beside the item that caused it as a small amber badge; Show scrolls to the problem and Fix applies the one-click repair when one exists. The rules cover off-canvas pixels, missing sockets, unlinked inks, an unused gem colour, and a body-change guard. Checks advise; they never block Save - a shipped look is sometimes on purpose.

Review gear

When a body changes shape (a new silhouette, a wider plate, a new held cut), the Forge opens a before / after / diff dialog with a small contact sheet of every pose the piece rides in. Accept the review and the new goldens take it; step through each item and the diff so a stray pixel is caught before the tool writes.

Goldens that follow saves

An item look has a golden - a small recorded snapshot of the pixels the tool painted - and every save moves exactly the goldens that item touched. The whole suite goes green again the moment you save a change, so a Gear Forge edit never leaves a red test behind on purpose.

Live reload and Try on in game

A running client checks once a second for a changed gear sheet, a changed item-icon file, or a new try-on request. When one appears the game repaints the affected sprite in place - no restart, no reload of the world. Press Try on in game in the Forge and the Freeroam character you are looking at picks up the piece within a second; Take off puts it back. Item-rule changes (accuracy, power, skills) still want a restart - only the looks hot-reload.

Forge a set

Once one tier is right, Forge a set remakes a whole set in a different tier in one dialog. Names, scaled armour, power and accuracy, harder recipes, ingredients that follow the set, and icons recoloured through a small palette the designer can tune. New colours you introduce join the shared icon palette. What used to be an axe at bronze comes out as an axe at iron, steel, silver, or adamantite - same art path, one save per tier.

Effects, engraved and glowing

The Effects panel picks what a piece does when it swings: a colour trail on the arc, a hit pop, sparks, a soft dust, or a glow on the sprite itself. Every effect is one row on a shared assets/gear-fx.json; the client reloads the file live, so an effect change is on screen within a second of Save. Two trims exist for the head of a weapon: an engraved pattern on the blade, or a rim light on the haunches. See Gear Effects.

Per-frame touch-ups and ghosts

Touch up this frame opens the small overlay for the exact pose the preview is on, and the tool checks on save that no stale touch-up is left behind on a frame the item no longer has. Ghost of saved paints the last save as a transparent overlay so a change reads at a glance, and Before / after puts the previous render next to the new one on the same pose.

Delete, bring back, and the small-pieces rule

The Gear Forge can delete an item and bring it back later - the row keeps its id, only its look and rules are hidden while deleted. One lint rule guards small pieces (gloves, a belt, a mask, an amulet, an earring): a piece that paints nothing over a body frame is flagged so it never ships as a phantom wearable.

An item preview in the panel

The Admin Panel's Give box shows a small preview of any item you are about to hand out - the icon at real size and, when the item is worn, a preview of it drawn on the character it fits. An operator sees what they are about to give.

The registry fingerprint

Both the client and the world read the same items file. On join the world sends its registry fingerprint - a short hash of every registry row - and a client whose file differs says so instead of pretending to name pieces it cannot see. Same fingerprint, same items on both sides; different, an honest "the world knows items I do not" notice.
