CONTRIBUTING

Contributing to the Wiki

This wiki is a small static site in the same pattern as the public porch site: plain HTML, one shared stylesheet, one tiny script, root-absolute links. No build step, no npm, no external fonts, no external scripts. Every number on a page is checked against the game's own source.

Source of truth

Every skill, item, tile, recipe, style and constant the wiki mentions lives in one file: server-architecture/crates/shared/src/lib.rs (with the mob sheet in assets/mob-stats.json and the creature registry in assets/creatures.json). The world, the client, the painter and the panel all read that file. So must a wiki page.

When the shared file changes, the wiki page and the test pin must move in the same change. A page that lags a registry is worse than no page at all - it teaches the wrong number.

The one-list chrome

Every page in this folder is registered in exactly one place: the PAGES array at the top of site.js. That list drives the brand jump dropdown, the icon rail and the sidebar; each page's group puts it on a shelf of either the player wiki or the Builder Wiki, and the chrome only shows the shelves of the wiki you are in. Add a page to PAGES and a matching {href, match, label, icon} row, add a small inline-SVG icon to ICONS keyed by that name, list it under its shelf in index.html (player pages) or builders.html (builder pages), and the whole chrome updates. A wiki test walks every *.html on disk and refuses the change if any page is missing from PAGES.

ASCII only, always

The game's native Bevy font carries no glyph past printable ASCII (U+0020 to U+007E). Every page here follows the same rule so the wiki text can be pasted straight into the client without becoming a rectangle. That means:

  • Straight quotes, not curly.
  • A hyphen - for a dash.
  • Three dots ... for an ellipsis.
  • (c) for the copyright symbol.
  • / for a slash separator; | for a pipe.
  • No Unicode glyphs as icons. Every icon on this site is inline SVG. A test walks every page, CSS and JS byte-for-byte and refuses a file that contains a code point outside ASCII.

Root-absolute links only

Pages link with /woodcutting.html, not woodcutting.html. The site is served from a site root, and a hosted copy must keep working when it moves from a subfolder to a domain root. The same rule applies to images: /assets/foo.png.

Images live in this folder

Every <img> must load from /assets/ inside this folder. A wiki test walks every page, extracts every src, and asserts the file exists on disk. If you want to show a new piece of art, copy it into assets/ first, then reference it. This is what lets the wiki be dropped onto any static host and still show its own pictures.

What not to document

Do not name launch scripts, local ports, environment variables, file paths inside the repo, or anything else about how the developer tools run. Those are for the game's internal design notes. This wiki is for players and builders, so it talks about what the game does, not what a developer's build folder is called.

Writing for players

Use plain language. "The health bar now shows HP and MP" reads better than "the vitals_bar widget accepts a label param". Group by what a player sees, not by what file changed. Developer-only tools (map painter, character forge, model maker) each get their own page.

The tests

Run the wiki contract from the repo root:

node --test greenhaven-wiki/tests/wiki.test.mjs

The suite checks that every page exists, that every page appears in the chrome, that every table matches the shared registry, that every image resolves on disk, that every page loads the shared theme before its own styles, and that every page stays ASCII-only and free of external URLs. A failing test is a real drift: fix the page or the pin in the same change that moves the source.

Editing an existing page

  1. Find the number in the shared file, not in a page.
  2. Change the page and the test pin in the same commit. If the shared file changes, that commit is the one that ships.
  3. Add a "how a rule works" line - never just the number. A wiki reader wants the shape of the system, not a table row.
  4. Cross-link to related pages. The hub is short; every page reaches one or two neighbours.

Where to send a change

This wiki is part of the game repository. The pages live in the greenhaven-wiki/ folder of the same repo as the game code, so a page change and the code change it describes land in one commit. There is no second wiki checkout, no separate repository to push, and no pointer to bump.

Have an idea?

If a system you play with has no page, that page is the change. Start with the source of truth, add one page, register it in PAGES, add a card to the hub, and pin the numbers in tests/wiki.test.mjs. Small pages are welcome; a good page can be five lines long.
