Character Forge

Every character in Greenhaven - the wanderer, the jester, the wildlife, the mobs, the pet - comes out of the Character Forge inside the model maker. It composes a character from parts, then bakes it into the sprite sheet the game loads.

What it builds

  • A sprite sheet. The Forge outputs one JSON sheet per character: frames, palettes and pose indexes the game client reads directly.
  • Every action. Idle, walk, run, blink, chop, mine, cast, swing - each is a pose on the same sheet. The player sheet today carries 48 frames: idle, four walk directions, four run directions, an authored blink, and swing poses.
  • Walk styles. A walk is a clip, not a rule - the Forge bakes a per-character gait so a cow does not walk like a jester.

How you build one

The Forge is part-based. Pick a body plan, then snap on hair, face, torso, arms, legs, held items, and any overlay (a cape or a piece of worn gear). Every part carries its own palette, so a new colour is one field, not a repaint. A layout pass keeps the preview in view while you edit, and a "My characters" list remembers what you authored.

Describe it

There is a text path: type a short description - "an old historian with a green hood and a bent staff" - and the Forge picks a body plan, applies parts and colours, and gives you a starting point to tune by hand. It is not a black box: what it chose is what appears in the parts, so you can un-pick any of it.

The command line

The same editor is scriptable, so an agent or a build job can drive it without opening a browser. The CLI speaks plain words: presets, random, mood, set, save-spec, plus a --new-kind that mints a fresh character (registry row + sheet + palette) in one call. Two inspection modes help a script see what it drew:

  • Detail layer. Overlay the part boundaries on the frame so a script can verify a hat sits where the code says.
  • Frame inspection. Dump one frame's pixels as a legend so a script can assert a shape without opening an image.

How a sheet gets into the game

The Forge writes a JSON sheet into assets/models/. One command ("Add to game") registers the character: the shared creature registry, the mob-stats sheet (only if the new thing is a fight), the map painter's palette, and the atlas colour all take a row from the same spec. A new hostile mob is one row in each file, plus its sheet.

Where the gear overlays come from

Every wearable also has a gear sheet at assets/models/gear/<item>.json, fit to the player sheet by the same Forge pipeline. When the player character changes shape, refit the pieces so a helm still sits on the head and a platebody still covers the torso.
