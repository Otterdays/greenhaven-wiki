POLICY

The GUI-first Law

Every content workflow in Greenhaven must be fully usable from a GUI. A builder never opens a text file, a terminal, a code editor or a doc to make or ship content. If a capability has no GUI, it is not done.

The rule in one line

People make content by clicking. Scripts are engines behind buttons. Nothing in a content pipeline is a "you have to edit the JSON" step.

What that rules out

  • No raw JSON text boxes in any tool. If a value can be edited, it is a slider, a picker, a checkbox or a plain-word input.
  • No "run this script to build the map / item / character". Every build is a button the tool offers.
  • No "read this doc to understand the file format before you can add a row". If the tool needs it, the tool shows it.
  • No "open the code to add a new kind". Adding a kind is a data row, and a data row has a New button.
  • No error codes. Errors speak plain words beside the control that caused them.

What is still fine

  • Typing a name, a description, or a "make me a bronze axe with a gem top" line into a text field. That is a normal GUI input.
  • Command-line helpers for developers who want them - the CLI is an additional path, never the only one.
  • Config files for installs (ports, tokens, world IDs). Those are not content.

Where the law is enforced

The rule lives in the operator-facing docs on the game side (a project-wide rule and a checklist for each tool). On the wiki side it shapes what a page can promise: if the wiki tells a builder "edit this file to add a new rot", and there is no GUI for it, the wiki is documenting unfinished work and the tool owes a GUI.

Which tools follow it

ToolStatus
Map painterGUI-first. Every tile, prop, character and resource-node override has a picker or a slider.
Model maker / Character ForgeGUI-first. Parts, colours and pose editing all live in the tool; a CLI sits alongside, never instead.
Gear ForgeGUI-first. Every icon, held and worn look is painted by the tool; the item data row it writes is invisible to the builder.
Music makerIn progress. The workshop script is still the only path; a GUI panel is the open next step.
Cursor makerGUI-first.
Launch panelNot a content tool - it is install plumbing, so the rule does not apply.

Why it exists

A greenhaven build should feel like making a build. A tool that needs a text editor at one step is a tool that loses the person in front of it at that step. Keeping the content path clickable is what makes a small team (or one operator) able to move fast without a codebase open.
